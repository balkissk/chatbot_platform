1. SEQUENCE DIAGRAM - CREER UN PROJET
================================================================================

A. CURRENT IMPLEMENTATION FLOW

1. Le Manager ouvre la page Projects.
   - Composant Angular : ProjectsComponent.
   - Route frontend : /dashboard/projects.

2. Le Manager ouvre le formulaire/modal de creation.
   - Methode frontend : openCreateModal().
   - Effet : createModalOpen = true.

3. Le Manager saisit les champs du projet.
   - newProjectName.
   - newProjectDescription.

4. Le Manager confirme la creation.
   - Methode frontend : ProjectsComponent.createProject().

5. Validation frontend minimale.
   - Le nom est trimme.
   - Si le nom est vide, la methode retourne immediatement.
   - Aucun appel backend n'est envoye dans ce cas.

6. Appel du service frontend.
   - ProjectsComponent appelle ApiService.createProject(data).

7. Appel HTTP.
   - ApiService envoie POST /projects.

8. Route backend.
   - Fichier : backend/routes/project_routes.py.
   - Fonction : create_project().

9. Verification d'authentification et de role.
   - Dependency : current_user = Depends(require_roles("admin", "manager")).
   - Acteurs autorises dans le code actuel : Manager et Administrator.
   - Si utilisateur non authentifie : 401.
   - Si role non autorise : 403.

10. Validation backend du nom.
    - Le backend trimme project.name.
    - Si le nom est vide : HTTP 400, detail "Project name is required".

11. Valeurs appliquees cote backend.
    - name = nom trimme.
    - description = project.description.strip() or "No description".
    - user_id = current_user.id.
    - status = ProjectStatus.active.value, donc "active".

12. Creation de l'entite Project.
    - Modele : Project.
    - Table : projects.
    - Champs importants : id, name, description, user_id, status, created_at, archived_at, deleted_at.

13. Ecriture base de donnees.
    - db.add(new_project).
    - db.commit().
    - db.refresh(new_project).

14. Creation de l'audit log.
    - Service : record_audit_log().
    - Action : PROJECT_CREATED.
    - resource_type : project.
    - resource_id : nouvel id du projet.
    - resource_name : nom du projet.

15. Reponse backend.
    - Retourne serialize_project(new_project, stats).
    - La reponse contient notamment id, name, description, user_id, status, created_at, counts/statistiques.

16. Traitement frontend en succes.
    - Vide newProjectName.
    - Vide newProjectDescription.
    - Ferme le modal : createModalOpen = false.
    - creating = false.
    - Affiche un toast : "Project created".
    - Recharge la liste via loadProjects().

17. Navigation apres creation.
    - Pas de navigation automatique verifiee.
    - La page reste sur la liste des projets et recharge les donnees.

C. MAIN MESSAGES

1. Manager -> Projects UI : ouvrir le modal de creation.
2. Manager -> Projects UI : saisir nom et description.
3. Projects UI -> ProjectsComponent : soumettre la creation.
4. ProjectsComponent -> ApiService : createProject(name, description).
5. ApiService -> FastAPI Project Route : POST /projects.
6. Project Route -> Auth : verifier role admin ou manager.
7. Project Route -> Project Route : valider le nom.
8. Project Route -> Project : creer l'objet Project.
9. Project Route -> Database : inserer Project.
10. Project Route -> AuditLog : creer PROJECT_CREATED.
11. Project Route -> Database : inserer AuditLog.
12. Project Route -> ApiService : retourner ProjectResponse.
13. ApiService -> ProjectsComponent : succes.
14. ProjectsComponent -> Projects UI : vider formulaire, fermer modal, afficher toast, recharger la liste.

2. SEQUENCE DIAGRAM - CREER UN ASSISTANT CONVERSATIONNEL
================================================================================

A. CURRENT IMPLEMENTATION FLOW

1. Le Manager ouvre la page des assistants d'un projet.
   - Route frontend : /dashboard/projects/{projectId}/chatbots.
   - Composant : ChatbotsComponent.

2. Le Manager clique sur l'action de creation d'assistant.
   - Methode : ChatbotsComponent.openWizard().

3. Verification frontend du statut du projet.
   - Si le projet est archive, openWizard() retourne sans ouvrir l'assistant creation wizard.
   - Cette restriction est cote frontend.

4. Ouverture du composant AssistantCreationWizardComponent.
   - Le wizard est un composant enfant de ChatbotsComponent.

5. STEP 1 - Assistant Purpose.
   - Question UI : "What kind of assistant do you want to create?"
   - Methode : selectAssistantType(value).
   - Cette selection est uniquement un etat frontend a ce moment.
   - Rien n'est persiste immediatement.

6. Valeurs disponibles pour Assistant Purpose.
   - Customer Support Assistant : customer_support.
   - Employee Knowledge Assistant : employee_knowledge.
   - Training & Certification Assistant : training_certification.
   - Lead Generation Assistant : lead_generation.
   - Custom Assistant : custom.

7. Regle de validation STEP 1.
   - canContinue() retourne true seulement si state.assistant_type est renseigne.
   - Si aucune option n'est choisie, l'utilisateur ne peut pas passer a l'etape suivante.

8. STEP 2 - Creation Mode.
   - Question UI : "How do you want to start?"
   - Methode : selectCreationMode(value).
   - Cette selection est uniquement un etat frontend a ce moment.
   - Rien n'est persiste immediatement.

9. Valeurs disponibles pour Creation Mode.
   - Start From Scratch : scratch.
   - Use Template : template.
   - Build With AI : ai.

10. Effet du choix Start From Scratch.
    - Pendant la creation backend, un assistant est cree avec une premiere version draft et un flow blank.
    - Apres creation, le frontend redirige vers Flow Builder.

11. Effet du choix Use Template.
    - Pendant la creation backend, l'assistant est cree avec une premiere version draft et un flow blank.
    - Le template n'est pas applique pendant la creation.
    - Apres creation, le frontend redirige vers la page Template Selection.

12. Effet du choix Build With AI.
    - Pendant la creation backend, l'assistant est cree avec une premiere version draft et un flow blank.
    - La generation IA n'est pas executee pendant la creation.
    - Apres creation, le frontend redirige vers la page AI Generator.

13. Regle de validation STEP 2.
    - canContinue() retourne true seulement si state.creation_mode est renseigne.

14. STEP 3 - Basic Configuration.
    - Champs UI :
      - Assistant Name.
      - Description.
      - Language.
      - Channel.

15. Valeurs de langue disponibles.
    - English : en.
    - French : fr.
    - Valeur par defaut du wizard : fr.

16. Valeurs de channel disponibles.
    - Public Chat : public_chat.
    - Web Widget : web_widget.
    - REST Public API : rest_public_api.
    - Valeur par defaut du wizard : web_widget.

17. Regles de validation STEP 3.
    - Le nom est obligatoire.
    - La langue est obligatoire.
    - Le channel est obligatoire.
    - La description est optionnelle.

18. Confirmation de creation dans le wizard.
    - Methode : AssistantCreationWizardComponent.finish().
    - Condition : canFinish() doit retourner true.
    - Le wizard emet finishWizard avec l'etat normalise.

19. Reception par ChatbotsComponent.
    - Methode : ChatbotsComponent.finishWizard(state).

20. Construction du payload frontend.
    - assistant_type = state.assistant_type.
    - creation_mode = state.creation_mode.
    - name = state.name.trim().
    - description = state.description?.trim() || "".
    - language = normalizeAssistantLanguage(state.language).
    - project_id = this.projectId.
    - type = "builder".
    - purpose = state.assistant_type.
    - mode = "builder".
    - channel = normalizeAssistantChannel(state.channel).
    - build_method = state.creation_mode.
    - template_key = null.
    - status = "draft".
    - published = false.

21. Appel du service frontend.
    - ApiService.createChatbot(data).

22. Appel HTTP.
    - POST /chatbots.

23. Route backend.
    - Fichier : backend/routes/chatbot_routes.py.
    - Fonction : create_chatbot().

24. Verification d'authentification et role.
    - current_user = Depends(require_roles("admin", "manager")).
    - Acteurs autorises dans le code actuel : Manager et Administrator.

25. Verification d'ownership projet.
    - Fonction : ensure_project_access(db, chatbot.project_id, current_user).
    - Si current_user.role == "manager", la requete ajoute Project.user_id == current_user.id.
    - Si le projet n'existe pas ou n'appartient pas au Manager : 404 "Project not found".

26. Validation backend du nom.
    - name = chatbot.name.strip().
    - Si vide : 400 "Chatbot name is required".

27. Validation backend du mode de creation.
    - build_method = creation_mode ou build_method ou "scratch".
    - Valeurs acceptees : scratch, template, ai, blank.
    - Si build_method == "blank", il est transforme en scratch.
    - Si valeur inconnue : 400 "Unsupported assistant creation mode".

28. Validation backend du template.
    - Si build_method == "template" et chatbot.template_key est fourni, la cle doit exister dans TEMPLATES.
    - Dans le flux actuel du wizard, template_key est envoye a null.
    - Donc aucun template n'est applique pendant la creation.

29. Validation backend de la langue.
    - Schema : ChatbotCreate.validate_language().
    - Valeurs supportees : en, fr.
    - Alias acceptes : english, anglais, french, francais.
    - Valeur par defaut de fallback schema : fr.

30. Validation backend du channel.
    - Schema : ChatbotCreate.validate_channel().
    - Valeurs supportees : public_chat, web_widget, rest_public_api.
    - Alias acceptes : public, web, web_chat, widget, rest_api, public_api, api.
    - Valeur par defaut de fallback schema : web_widget.

31. Creation de l'entite Chatbot.
    - Champs principaux :
      - name.
      - description.
      - language.
      - type.
      - purpose.
      - mode.
      - channel.
      - build_method.
      - template_key.
      - source_template_key.
      - source_template_version.
      - ai_assistant_goal.
      - ai_business_context.
      - ai_knowledge_base_description.
      - public_api_key.
      - public_api_enabled = True.
      - project_id.
    - is_active n'est pas fixe explicitement dans create_chatbot(), mais le modele Chatbot definit default=True.

32. Ecriture base de donnees 1.
    - Insert Chatbot.

33. Creation de la premiere version.
    - Entite : VersionChatbot.
    - Champs :
      - chatbot_id = new_chatbot.id.
      - version_number = 1.
      - status = "draft".
      - created_by = current_user.id.

34. Ecriture base de donnees 2.
    - Insert VersionChatbot.

35. Creation de la configuration LLM initiale.
    - Entite : LLMConfig.
    - Champs :
      - version_id = first_version.id.
      - model = "phi3".
      - temperature = 0.7.
      - system_prompt = chatbot_language_instruction(new_chatbot.language).

36. Ecriture base de donnees 3.
    - Insert LLMConfig.

37. Creation du flow initial.
    - Fonction : create_starter_flow(db, first_version.id, "blank", new_chatbot.language).
    - Le flow initial est blank.

38. Ecriture base de donnees 4.
    - Insert Flow et structure starter associee.

39. Audit log.
    - Action : CHATBOT_CREATED.
    - resource_type : chatbot.
    - resource_id : new_chatbot.id.
    - resource_name : new_chatbot.name.
    - metadata : project_id.

40. Reponse backend.
    - Retourne serialize_chatbot(new_chatbot, stats).
    - La reponse contient notamment :
      - id.
      - name.
      - description.
      - language.
      - purpose / assistant_type.
      - mode.
      - channel.
      - build_method / creation_mode.
      - is_active.
      - status calcule "draft" ou "published".
      - published.
      - active_version_id.
      - public_api_key.
      - public_api_enabled.
      - rag_settings.
      - project_id.
      - compteurs de versions.

41. Traitement frontend en succes.
    - creating = false.
    - wizardOpen = false.
    - success = "Assistant created as draft. Assistant ID: {created.id}".
    - Appel de navigateAfterCreation(state.creation_mode, created.id).

42. Redirection selon le mode.
    - Si scratch :
      /dashboard/projects/{projectId}/chatbots/{chatbotId}/flow.
    - Si template :
      /dashboard/projects/{projectId}/chatbots/{chatbotId}/templates.
    - Si ai :
      /dashboard/projects/{projectId}/chatbots/{chatbotId}/ai-generator.

3. SEQUENCE DIAGRAM - MODIFIER LA CONFIGURATION GENERALE D'UN ASSISTANT
================================================================================

A. CURRENT IMPLEMENTATION FLOW

1. Le Manager ouvre la page Assistant Settings.
   - Route frontend :
     /dashboard/projects/{projectId}/chatbots/{chatbotId}/settings.
   - Composant : AssistantSettingsComponent.

2. Initialisation de la page.
   - Methode : ngOnInit().
   - Lit projectId et chatbotId depuis les parametres de route.
   - Appelle loadPage().

3. Chargement du projet.
   - AssistantSettingsComponent appelle ApiService.getProject(projectId).
   - Endpoint backend : GET /projects/{project_id}.
   - Utilise la verification d'ownership projet pour Manager.

4. Chargement de l'assistant.
   - AssistantSettingsComponent appelle ApiService.getChatbot(chatbotId).
   - Endpoint backend : GET /chatbots/{id}.

5. Verification backend pour lire l'assistant.
   - Route : get_chatbot_details().
   - Permission : require_roles("admin", "manager").
   - Ownership : get_accessible_chatbot().
   - Pour Manager, get_accessible_chatbot() appelle ensure_project_access() sur le projet de l'assistant.
   - ensure_project_access() verifie Project.user_id == current_user.id pour Manager.

6. Reponse backend de l'assistant.
   - Retourne les details serialises de l'assistant.

7. Remplissage du formulaire.
   - Methode frontend : populateForm(assistant).
   - Champs charges :
     - name.
     - description.
     - language.
     - channel.
     - type = "builder".
     - purpose.
     - mode = "builder".
     - template_key.

8. Champs editables selon le code actuel.
   - name : editable.
   - description : editable.
   - language : editable.
   - channel : editable.
   - purpose : le backend accepte la modification et le formulaire conserve cette valeur.

9. Champ immutable selon le backend.
   - creation mode / build_method.
   - Si build_method ou creation_mode est envoye et different de chatbot.build_method, backend retourne 400 "Assistant creation mode cannot be changed after creation".

10. Le Manager modifie la configuration generale.

11. Le Manager clique sur Save.
    - Methode : AssistantSettingsComponent.saveSettings().

12. Validation frontend du nom.
    - name = this.form.name.trim().
    - Si vide : error = "Assistant name is required", aucun appel API.

13. Construction du payload frontend.
    - Envoie les champs du formulaire avec :
      - type = "builder".
      - mode = "builder".
      - name trimme.
      - description trimmee.
      - language normalisee.
      - channel normalise.

14. Appel du service frontend.
    - ApiService.updateChatbot(chatbotId, data).

15. Appel HTTP.
    - PUT /chatbots/{id}.

16. Route backend.
    - Fichier : backend/routes/chatbot_routes.py.
    - Fonction : update_chatbot().

17. Verification d'authentification et role.
    - current_user = Depends(require_roles("admin", "manager")).

18. Verification ownership assistant.
    - Fonction : get_accessible_chatbot(db, id, current_user).
    - Verifie que l'assistant existe.
    - Verifie que son projet est accessible.
    - Pour Manager : le projet doit avoir Project.user_id == current_user.id.

19. Validation backend du nom.
    - name = payload.name.strip().
    - Si vide : 400 "Chatbot name is required".

20. Validation backend langue/channel.
    - Schema : ChatbotUpdate.
    - Langues supportees : en, fr.
    - Channels supportes : public_chat, web_widget, rest_public_api.

21. Validation de l'immutabilite du mode de creation.
    - requested_build_method = payload.creation_mode or payload.build_method.
    - Si requested_build_method existe et differe de chatbot.build_method :
      400 "Assistant creation mode cannot be changed after creation".

22. Mise a jour backend.
    - chatbot.name = name.
    - chatbot.description = payload.description.strip().
    - chatbot.language = payload.language.
    - chatbot.type = payload.type.
    - chatbot.purpose = payload.purpose.
    - chatbot.mode = payload.mode.
    - chatbot.channel = payload.channel.

23. Ecriture base de donnees.
    - db.commit().
    - db.refresh(chatbot).

24. Audit log.
    - Action : CHATBOT_UPDATED.
    - resource_type : chatbot.
    - resource_id : chatbot.id.
    - resource_name : chatbot.name.
    - metadata : project_id.

25. Reponse backend.
    - Retourne serialize_chatbot(chatbot).

26. Traitement frontend succes.
    - Met a jour assistant signal.
    - Repopule le formulaire avec les valeurs retour.
    - saving = false.
    - message = "Assistant settings saved".
    - toast success "Assistant settings saved".

D. ALT / ERROR BLOCKS

ALT 1 - Nom vide cote frontend :
- saveSettings() bloque l'envoi.
- Message : "Assistant name is required".

ALT 2 - Utilisateur non authentifie :
- Backend retourne 401.

ALT 3 - Role non autorise :
- Backend retourne 403.

ALT 4 - Assistant introuvable ou non possede par Manager :
- get_accessible_chatbot() retourne 404 "Chatbot not found".

ALT 5 - Nom vide cote backend :
- Backend retourne 400 "Chatbot name is required".

ALT 6 - Langue ou channel non supporte :
- Validation schema echoue.

ALT 7 - Tentative de modification du mode de creation :
- Backend retourne 400 "Assistant creation mode cannot be changed after creation".

ALT 8 - Projet archive :
- Le frontend expose isArchivedProject() et peut desactiver certaines actions.
- La route backend update_chatbot() ne semble pas bloquer explicitement une mise a jour si le projet est archive.
- A mentionner comme restriction UI, pas comme regle backend verifiee.

- Tous les champs serialises de la reponse.
- API key, RAG settings ou deployment channels, car ils ne font pas partie de la configuration generale demandee.
- Setup wizard edit-mode pour template/AI regeneration, car c'est un scenario distinct.
